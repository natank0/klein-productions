# מפת עקרונות והחלטות

המבנה כאן הוא: מקור מקצועי → עיקרון → החלטת יישום. זוהי סינתזה יישומית; אין לראות בניסוחים ציטוטים מן הספרים.

| תחום | עיקרון | החלטת יישום באתר |
|---|---|---|
| בהירות ומשימה | Krug: המשתמש אינו אמור לפענח מה האתר מציע או מה הפעולה הבאה | H1 ישיר, טלפון גלוי, פעולה ראשית אחת בכל אזור ומסלול קצר מסוג אירוע לטופס |
| היררכיה | *Refactoring UI* ו-Lupton: משקל, קנה מידה, ריווח וקיבוץ קודמים לקישוט | סולם מרווחים מוגבל, שתי דרגות משקל, כותרות מיושרות לתוכן ואורך שורה מוגבל |
| גריד וקומפוזיציה | Samara ו-Clarke: מבנה עקבי מאפשר חריגה מכוונת ומובחנת | גריד פשוט שנפתח לעמודה אחת; קווי פתיחה וגל יחיד במקום רשת כרטיסים גנרית |
| מותג | Wheeler: זהות נוצרת ממערכת עקבית של נקודות מגע | כחול עמוק לטקסט ולסיום, כחול פעולה, אמבר כמבטא קטן, ירוק רק לוואטסאפ |
| כתיבה | Podmajersky: שם הפעולה צריך לתאר את התוצאה האמיתית | “פתיחת הודעה בוואטסאפ”; אין ניסוח הטוען שהפנייה נשלחה או נשמרה |
| טפסים | Silver ו-Pickering: בקשו רק מידע נחוץ, שמרו הקשר ותנו שגיאה סמוכה ומעשית | חמישה שדות ראשיים, פרטי רשות ב-disclosure, מיקוד בשגיאה הראשונה וחלופת חיוג/העתקה |
| נגישות | Pickering + WCAG 2.2: סמנטיקה ו-progressive enhancement לפני JS | `details/summary`, תפריט עם מצב מורחב, focus גלוי, reduced motion, forced colors ותפקוד בלי JS |
| פריסה רספונסיבית | *Every Layout*: תנו לתוכן ולמרחב לקבוע את הפריסה | Grid/Flex עם `minmax`, `clamp` ו-reflow; אין הסתמכות על רוחב מסך יחיד |
| מחקר ואמינות | Hall: הפרידו תצפית, השערה וטענה מוכחת | אין להמציא משתמשים, המרות או שירותים; עובדה לא מאומתת אינה מוצגת באתר |

## כללי הכרעה

1. אמינות ופונקציונליות קודמות לליטוש חזותי.
2. בדיקה אוטומטית מגינה על דרישה, לא על פתרון עיצובי היסטורי ללא הצדקה.
3. שינוי חזותי מהותי דורש השוואה באותם viewport ומצב תוכן.
4. ממצא מצילום מסך אינו הוכחת נגישות מלאה; מקלדת, קורא מסך, zoom ומכשירים אמיתיים נבדקים בנפרד.
5. החלטה נוכחית נקבעת לפי הקוד, האתר החי והנחיית המשתמש האחרונה — לא לפי מסמך handoff ישן.
