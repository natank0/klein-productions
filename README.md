# קליין הפקות – אתר

אתר סטטי (HTML, CSS ו-JavaScript מצומצם, בלי שרת ובלי שירותי צד שלישי) לעסק ההגברה "קליין הפקות".

- אתר חי: https://natank0.github.io/klein-productions/
- פרסום: GitHub Pages מהענף `main` (תיקיית השורש).

## מבנה
- `index.html` – דף האתר בבני ברק
- `sitemap.xml` – מפת אתר לחיפוש (לשליחה ב-Search Console)
- `404.html` – עמוד לכתובות שלא קיימות (למשל עמוד בית שמש הישן), עם קישור לדף הראשי, חיוג ווואטסאפ
- `assets/css/site.css` – עיצוב משותף (שזיף וזהב מהלוגו, נייר חם לקריאה; גופני מערכת)
- `assets/js/site.js` – תפריט מובייל וטופס הצעת מחיר שפותח הודעת וואטסאפ מוכנה
- `tests/run.js`, `package.json`, `.htmlvalidate.json` – בדיקות אוטומטיות (לא חלק מהאתר)
- `.github/workflows/qa.yml` – הרצת הבדיקות בכל PR
- `assets/img/` – לוגו מכווץ (`logo-88/132` ב-WebP ו-JPG), אייקונים ותמונת שיתוף. `logo-full.jpg` הוא קובץ המקור.

## עיצוב: צבע ומקצב
- **פלטה מתוך הלוגו:** הגוונים נדגמו מ-`assets/img/logo-full.jpg` (רקע סגול-שחור, זהב). הטוקנים בראש `site.css`: `--plum-950/900/800/700`, `--gold-300/400/500/700`, ולצידם נייר חם לקריאה.
- **מקצב משטחים:** כותרת בהירה, מסך פתיחה כהה, חתונות ושאר האירועים על נייר, "מה כולל השירות" כהה, המחסן על נייר חם, שאלות וטופס בהירים, פוטר כהה.
- **חתונות וחופות** הן כניסת הדגל (`#weddings`), לפני ארבע הקבוצות האחרות (`#more-events`).

## המחסן בבני ברק (פרק `#areas`)
- **מה מוצג:** המחשה סכמטית של עיר ו**פין אחד בלבד**: "מחסן קליין הפקות, כהנמן 64". אין נקודות נוספות, אין מרחקים, אין זמני הגעה ואין טענה ל"מרכז גאוגרפי".
- **ההמחשה אינה מפה:** הרחובות ב-SVG מופשטים ואינם מבוססים על נתוני מפה. כך כתוב גם בכיתוב שמתחתיה. ה-SVG הוא `aria-hidden`, והכתובת מופיעה כטקסט רגיל לצידו.
- **פריסה:** בדסקטופ טקסט וכפתורים לצד ההמחשה; במובייל קודם כתובת וכפתורי ניווט, ואחריהם ההמחשה (4:3). חוד הפין תמיד במרכז ההמחשה.
- **בלי תנועה ובלי JavaScript:** המודול סטטי לגמרי.
- **מפה אמיתית בעתיד:** אם רוצים רחובות אמיתיים, מפיקים SVG מנתוני OpenStreetMap (רישיון ODbL, עם ייחוס גלוי), אחרי אימות מיקום הכניסה למחסן מול בעל העסק. לא משתמשים בצילום מסך של Google Maps.

### כפתורי Waze ו-Google Maps
- הקישורים מחפשים את הכתובת "כהנמן 64 בני ברק" ולא קואורדינטות. מעבר לנקודה קבועה רק אחרי אימות הכניסה.
- **סמלים רשמיים:** הכפתורים מוכנים לקבל את הסמל הרשמי בצבעיו המקוריים, אבל הקבצים עוד לא נוספו. צריך להוריד אותם ממרכזי המותג הרשמיים (Google Maps: Partner Marketing Hub; Waze: Brand Hub דרך waze.com/contact), לבדוק את תנאי השימוש, ולשמור אותם מקומית:
  - `assets/img/brands/waze-icon.svg`
  - `assets/img/brands/google-maps-icon.svg`

  ואז מוסיפים בתוך כל קישור `.navigation-link`, לפני ה-`<span>`:

```html
<img src="assets/img/brands/waze-icon.svg" alt="" width="24" height="24">
```

- אין לצבוע את הסמלים מחדש, להחיל עליהם `filter` או לשרטט אותם מחדש. הטקסט נשאר לצד הסמל. הבדיקות מוודאות שקובץ שנוסף אכן מוצג בקישור הנכון, ושאין `filter`.

## בדיקות (`npm test`)
- **התקנה והרצה:** `npm ci`, `npx playwright install chromium`, ואז `npm test`. התלויות משמשות לבדיקות בלבד ולא נטענות באתר.
- **מתי הן רצות:** בכל PR ובכל דחיפה ל-`main` (`.github/workflows/qa.yml`). מיזוג רק כשהבדיקות ירוקות.
- **מה נבדק** (`tests/run.js`; כל כלל של הפרויקט הוא בדיקה):
  - **HTML:** תקינות לפי html-validate (`.htmlvalidate.json`).
  - **כללי תוכן:** אין טענות שלא אושרו ("המובילים", "סניף", ותק, מחירים), מספר טלפון אחד, ואין משאבים חיצוניים.
  - **אבטחה:** CSP בלי `unsafe-inline`, hash תואם לכל סקריפט מוטבע, אין `style` מוטבע, וקישורים לחלון חדש עם `noopener`.
  - **פריסה בעשרה רוחבים (320 עד 1920):** אין גלילה אופקית, אזורי מגע של 44px לפחות, כפתורי Waze ו-Google Maps בגובה 48px לפחות ובלי חיתוך, הפין והתווית בתוך ההמחשה וחוד הפין במרכזה, הכתובת והכפתורים לפני ההמחשה במובייל. אין שגיאות, אין הפרות CSP ואין בקשות חיצוניות.
  - **המחסן:** פין אחד, אין שמות אולמות או קוד רדאר/גלריה בשום קובץ שנפרס (כולל README), קישורי Waze ו-Google Maps לכתובת המחסן עם טקסט גלוי, וההמחשה מוצהרת כסכמטית.
  - **נגישות:** axe בלי הפרות (WCAG 2.2 AA). ניגודיות על המשטחים הכהים והמדורגים (מסך הפתיחה, כניסת החתונות, תווית הפין) נמדדת פיקסל אחר פיקסל.
  - **טופס:** תגי אירוע, כפתור החתונות, שמירת בחירה, צרכים מוצעים לפי סוג האירוע (בלי לסמן בשביל הפונה), "טרם נקבע", 7 מקרי טלפון, תאריך שעבר, יום שבת, 400 תווים, עיר "אחר" עם שם העיר בהודעה, והעתקה. וואטסאפ מיורט, ושום הודעה לא נשלחת.
  - **תנועה, בלי JS, ו-404.**
- **הרצה מקומית עם Chrome קיים:** `CHROME_PATH=/usr/bin/google-chrome npm test`.

## אבטחה ופרטיות
- **CSP קשיח** בתגית meta:
  - `default-src 'none'`, וסקריפטים וסגנונות רק מהאתר.
  - סקריפט מוטבע אחד מאושר ב-hash. אם משנים אותו, מעדכנים את ה-hash, והבדיקות מזכירות.
  - `connect-src 'self'` מאפשר בקשות רק לאתר עצמו, למשל כשבודקי SEO קוראים את `robots.txt`.
- **גרסאות לקבצים (`?v=`):** GitHub Pages שומר CSS ו-JS במטמון הדפדפן 10 דקות. אחרי כל שינוי ב-`site.css` או ב-`site.js` מריצים `npm run stamp`. הוא מעדכן את `?v=` לפי תוכן הקובץ, כך ש-HTML חדש לא נטען עם CSS ישן. הבדיקות נכשלות אם שוכחים.
- **בדיקה מול האתר החי:** `QA_BASE=https://natank0.github.io/klein-productions/ npm test`.
- **אין שירותי צד שלישי:** בלי גופנים, CDN, אנליטיקה או עוגיות. הטופס לא שולח נתונים לשום שרת, רק מכין הודעת וואטסאפ במכשיר של הפונה.
- **מגבלה ידועה:** GitHub Pages לא מאפשר כותרות HTTP, ולכן אין `frame-ancestors` ואין HSTS מותאם. בדומיין פרטי מאחורי CDN אפשר להוסיף אותן.

## פס החיוג במובייל
מוסתר כל עוד כפתורי מסך הפתיחה גלויים, וכשהמקלדת פתוחה בזמן הקלדה. בלי JavaScript הוא מוצג תמיד. הריווח שלו נמצא בתוך הפוטר, כך שהרקע הכהה מגיע עד תחתית המסך.

## הוספת תמונות בהמשך
העמודים שלמים גם בלי תמונות. כדי להוסיף תמונה לכניסה של סוג אירוע, מוסיפים בתוך `<article class="entry">`:

```html
<figure class="entry-media">
  <img src="assets/img/events/wedding-1200.webp" alt="תיאור התמונה" width="1200" height="525" loading="lazy" decoding="async">
</figure>
```

כדאי להעלות תמונות דחוסות (WebP, עד כ-150KB), בלי תמונות של נשים ובלי קהל מעורב.
